# 1130 - Jogo da Velha

## Contexto

Jogo da velha 1-D em um tabuleiro 1 × N: os jogadores alternam marcando um `X` em uma casa vazia, e quem formar três ou mais `X` consecutivos vence. Dado o tabuleiro, decidir se Maria (que joga agora) tem estratégia vencedora.

## Entrada

Vários casos: uma linha com N (3 ≤ N ≤ 10^4) e uma linha com N caracteres (`.` vazia, `X` marcada), nunca com três `X` seguidos. Termina com `0`.

## Saída

`S` se Maria tem estratégia vencedora, `N` caso contrário.

## Exemplo de Entrada

```text
5
.....
5
..X..
6
X.X.X.
12
............
0
```

## Exemplo de Saída

```text
S
N
S
N
```

## Forma de Resolução

1. **Vitória imediata:** se existe uma casa vazia que, marcada, forma `XXX` (padrões `XX.`, `.XX`, `X.X`), a resposta é `S`.
2. **Jogadas seguras:** sem vitória imediata, marcar uma casa a distância ≤ 2 de um `X` deixa o adversário vencer na jogada seguinte. Só jogadas em casas a distância ≥ 3 de qualquer `X` são viáveis; quem não tem jogada segura perde.
3. **Sprague-Grundy:** as casas seguras formam segmentos independentes de tamanho L. Jogar na posição i (0-indexada) deixa segmentos de tamanho $\max(0, i-2)$ e $\max(0, L-i-3)$:
$$G(L) = \text{mex}\{G(\max(0,i-2)) \oplus G(\max(0,L-i-3)) : 0 \le i < L\}$$
4. Maria vence se o XOR dos $G$ dos segmentos for diferente de zero.

### Exemplos do enunciado

- `.....`: sem `X`, um segmento de tamanho 5 com $G(5) = 2 \ne 0$ → `S`.
- `..X..`: todas as casas vazias estão a distância ≤ 2 do `X`, nenhum segmento seguro → XOR 0 → `N`.
- `X.X.X.`: marcar a casa 1 forma `XXX` (padrão `X.X`) → `S`.
- `............`: um segmento de tamanho 12, $G(12) = 0$ → `N`.

### Otimizações

- **Pré-computação de $G$:** os valores não são periódicos, então são calculados até o maior N da entrada. Para $L \ge 5$, jogar em $i$ com $2 \le i \le L-3$ gera os pares $(a, L-5-a)$, simétricos em $a$, então só metade deles é percorrida. As jogadas nas bordas ($i = 0, 1, L-2, L-1$) contribuem apenas $G(L-3)$ e $G(L-4)$.
- **Entrada/saída:** `stdin.readLineSync()` lê byte a byte e estoura o limite com muitos casos grandes. A entrada inteira é lida em blocos, interpretada direto dos bytes, e a saída é escrita de uma só vez.

## Complexidade

Pré-computar $G$ até o maior N da entrada custa $O(N^2)$ (uma única vez, cerca de $N^2/4$ operações); cada caso custa $O(N)$. Com 1000 casos de $N = 10^4$ (~10 MB), o programa roda em cerca de 0,4 s localmente.
