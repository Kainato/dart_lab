# 1024 - Criptografia

## 📌 Descrição

O objetivo deste algoritmo é criptografar uma linha de texto fornecida como entrada aplicando uma série de transformações baseadas em posições de caracteres, códigos ASCII e deslocamentos direcionais.

---

## 📋 Regras do Negócio

### 1. Primeira Etapa (Deslocamento de Letras)

Apenas os caracteres que forem letras maiúsculas ou minúsculas (alfabeto de `A`-`Z` e `a`-`z`) devem ter seus valores ASCII deslocados **3 posições para a direita** na tabela ASCII (ou seja, somar `3` ao valor do caractere, e.g., `'a'` vira `'d'`).

### 2. Segunda Etapa (Inversão da String)

Após aplicar a primeira etapa em todos os caracteres da linha, a string resultante deve ser **invertida** (o primeiro caractere passa a ser o último, o segundo passa a ser o penúltimo, e assim por diante).

### 3. Terceira Etapa (Deslocamento da Metade em Diante)

A partir da metade da string (truncada para inteiros, ou seja, índice `N / 2` onde `N` é o comprimento total) **até o final**, todos os caracteres devem ser deslocados **1 posição para a esquerda** na tabela ASCII (ou seja, subtrair `1` do valor do caractere).

---

## 📥 Estrutura de Entrada

- **Número de casos de teste ($N$):** A primeira linha de entrada contém um inteiro $N$ ($1 \le N \le 10^4$) que indica a quantidade de casos de teste.
- **Linhas seguintes:** Cada linha subsequente contém uma string $S$ contendo letras (maiúsculas e minúsculas), espaços, números ou símbolos, com comprimento entre $1$ e $1000$ caracteres.

## 📤 Estrutura de Saída

Para cada caso de teste, imprima a string criptografada correspondente em uma nova linha.

## Forma de Resolução

A solução implementa as três etapas de criptografia de forma otimizada:

1. **Pré-processamento com Lista de Códigos:** Em vez de manipular strings diretamente, a primeira etapa armazena os códigos ASCII em uma lista de inteiros
2. **Combinação de Etapas 2 e 3:** A inversão e o deslocamento da metade são realizados em um único loop, iterando de trás para frente
3. **Construção Final Otimizada:** A string final é construída uma única vez usando `String.fromCharCodes()`
4. **Leitura Assíncrona em Batch:** Todas as linhas de entrada são lidas de uma vez e armazenadas em memória antes do processamento

---

## 📝 Descrição da Resolução

### Pensamento do Problema

Este é um problema de transformação de strings com três etapas sequenciais. A abordagem ingênua (manipular strings intermediárias) causa problemas de performance em casos com muitas linhas e strings longas. A chave é evitar múltiplas conversões string-inteiro e operações que criam cópias desnecessárias.

### Otimizações Implementadas

#### 1. Trabalho com Códigos Inteiros

- Ao invés de manipular strings, armazenamos apenas os códigos ASCII em uma `List<int>`
- Isso evita a alocação de strings intermediárias
- Acesso aos códigos é direto e rápido via índice

#### 2. Combinação de Etapas 2 e 3

- **Etapa 2** (Inversão): Iterar de trás para frente
- **Etapa 3** (Deslocamento -1): Aplicar -1 na posição correta durante a iteração reversa
- Ambas são realizadas em um único loop O(n), não dois

#### 3. Cálculo Eficiente de Posição

```dart
int newPos = len - 1 - i;  // Posição após inversão
if (newPos >= midpoint) {
  result.add(charCode - 1);
}
```

#### 4. Leitura Assíncrona em Batch

- Usa `utf8.decoder` com streams para ler todas as linhas de uma vez
- Processa todas as linhas em memória
- Escreve a saída uma única vez no final

Esta abordagem reduz dramaticamente o overhead de I/O e manipulação de strings.

## �💡 Explicação Passo a Passo

### Exemplo: "abcde"

#### Etapa 1 - Deslocamento de Letras (+3)

Cada letra recebe +3 no seu valor ASCII:

```text
'a' (97) → 'd' (100)
'b' (98) → 'e' (101)
'c' (99) → 'f' (102)
'd' (100) → 'g' (103)
'e' (101) → 'h' (104)
```

Resultado após Etapa 1: **"defgh"**

#### Etapa 2 - Inversão da String

A string "defgh" é invertida:

```text
"defgh" → "hgfed"
```

Resultado após Etapa 2: **"hgfed"**

#### Etapa 3 - Deslocamento da Metade (-1)

Comprimento = 5, Metade = 5 / 2 = 2 (truncado)

- Índices 0-1: "hg" (mantém-se como está)
- Índices 2-4: aplica-se -1 no ASCII

```text
'f' (102) → 'e' (101)
'e' (101) → 'd' (100)
'd' (100) → 'c' (99)
```

Resultado final: **"hgedc"**

## ⏱️ Análise de Complexidade

### Função `encrypt(String line)`

- **Etapa 1 (Deslocamento):** O(n) - uma passagem pela string
- **Etapa 2+3 (Inversão + Deslocamento):** O(n) - uma passagem reversa pela lista
- **Conversão Final:** O(n) - `String.fromCharCodes()` percorre a lista

**Complexidade Total:** O(n) onde n é o comprimento da string

**Espaço:** O(n) para armazenar duas listas de inteiros

### Função `main()`

- **Leitura:** O(L) onde L é o tamanho total da entrada
- **Processamento:** O(N \* M) onde N é número de casos de teste e M é comprimento médio das strings
- **Escrita:** O(L) - uma única chamada a `stdout.write()`, onde L é o tamanho total da saída

## 🎯 Implementação em Dart

### Otimizações Chave Utilizadas

1. **Listas Tipadas (`<int>[]`):** Melhor performance que listas dinâmicas
2. **Acesso Direto via `codeUnitAt()`:** Sem conversão intermediária
3. **Divisão inteira (`~/`):** Calcula a metade truncando o resultado para um índice inteiro
4. **Streams Assíncronos:** Processamento eficiente de entrada em batch
5. **StringBuffer para Saída:** Evita múltiplas concatenações

### Código Principal

```dart
String encrypt(String line) {
  final codes = <int>[];

  // Etapa 1: Deslocar letras +3
  for (int i = 0; i < line.length; i++) {
    int charCode = line.codeUnitAt(i);
    if ((charCode >= 65 && charCode <= 90) ||
        (charCode >= 97 && charCode <= 122)) {
      codes.add(charCode + 3);
    } else {
      codes.add(charCode);
    }
  }

  int len = codes.length;
  int midpoint = len ~/ 2;
  final result = <int>[];

  // Etapas 2+3: Inverter e aplicar -1 na metade
  for (int i = len - 1; i >= 0; i--) {
    int charCode = codes[i];
    int newPos = len - 1 - i;

    if (newPos >= midpoint) {
      result.add(charCode - 1);
    } else {
      result.add(charCode);
    }
  }

  return String.fromCharCodes(result);
}
```

## ✅ Critérios de Aceite

- O algoritmo deve ler corretamente a quantidade de casos de teste $N$ e consumir a quebra de linha pendente antes de processar as strings.
- Deve tratar adequadamente espaços em branco e caracteres especiais sem alterar suas posições de forma incorreta nas etapas de deslocamento de caracteres.
- A divisão ao meio para a terceira etapa deve considerar exatamente a metade do tamanho da linha processada.
